How to use this document. Part I audits the existing proposal against the four reference papers in the repository and lists every defect that must be fixed before submission. Part II restates the research so the claimed contribution is defensible and no reviewer can find it already published. Part III–VI specify the software system to be built, module by module, with a day-by-day execution roadmap, the full experiment matrix, and the statistical protocol. Part VII–VIII define the documentation, governance and reporting standards the project must satisfy. Part IX maps the whole programme onto the thesis chapters. The appendix holds the operational reference material — environment pinning, configuration schema, data dictionary, glossaries and checklists.

Reading order. Team members should read Parts I, II and VI first. Workstream owners should then read the module specification for their own track in Part III. The supervisor should review Parts II, VI, VII and IX, which together define what will be examined.
