VIExperiment Matrix & Statistical Protocol

Part V says what to build. This Part specifies exactly what to run and what would count as a result. Its purpose is to make the evaluation impossible to argue with: every question in §2.3 maps to a specific experiment with a specific unit of analysis, a specific test, and a stated decision rule.

6.1 Target and label definition

TargetDefinitionTask typeUse
y_retlog(close[t+1] / close[t])RegressionThe primary target. Continuous, stationary, and directly convertible into a trading signal and a financial metric.
y_dir1 if y_ret > 0 else 0ClassificationSecondary. Direction is what most papers report, and it lets you compare directly with Dashtaki et al. (2025)'s accuracy figures. Report balanced accuracy, not raw accuracy alone.
y_ret_5dlog(close[t+5] / close[t])RegressionHorizon robustness. A sentiment signal that works at 1 day but not at 5 days has a short half-life — itself a finding worth reporting.

Table 6.1 — Target definitions. Fixing these once, at the start, prevents the D9 defect (mixing regression and classification metrics) from reappearing.

Why log returns and not price levels

A model trained to predict the price level of a crypto asset will appear to achieve very low RMSE, because the price is a large number and a large absolute error is a small percentage error. RMSE on price levels is uninterpretable and is not comparable across assets or across time. Wang (2026) predicts log returns; Wang & Huang (2026) compare on price. Predict log returns. If the thesis must report a price-level metric for comparability with a specific cited paper, report it in a clearly separated table with the percentage-error framing stated.

6.2 Nested feature sets

Feature sets are nested, which is what makes the incremental-value tests clean: each set strictly contains the previous one, so any performance difference is attributable to the added block and nothing else.

SetContentsApprox. sizeQuestion it answers
F1Technical indicators only (price + volume)~30How much does price and volume alone explain? This is the field's traditional baseline.
F2F1 + macro & cross-market~40Does macro add value over technical? (Wang 2026 found yes — this is our control condition.)
F3F2 + own-asset sentiment~48Does sentiment add value? This is the RQ2/H1 test at the model level.
F4F3 + cross-asset sentiment (contagion)~55Does other assets' sentiment add value beyond our own? This is the RQ3/H3 test — the key new experiment.
F5F4 + regime features~58Does regime conditioning add value? This is the RQ4/H4 test and C3's mechanism.

Table 6.2 — Nested feature sets. F1 ⊂ F2 ⊂ F3 ⊂ F4 ⊂ F5.

Two sets that must also be run

F3b — sentiment without the crypto weighting. Identical to F3 but using the plain Loughran–McDonald score instead of SentCrypto. The F3 vs F3b comparison is RQ1/H1 at the model level, and it directly extends Kreuzer et al. (2026)'s finding from regression to prediction.

F4b — cross-asset sentiment at lag 0 only. F4 with all lagged cross-asset features removed. Comparing F4 to F4b isolates the contribution of the lag structure specifically, rather than merely showing that cross-asset sentiment is useful. Without this comparison, H3 is not testable.

Minimum tier sample sizes

Before running anything, compute the achievable sample size per tier. This is a power calculation, and doing it before the experiments prevents an underpowered study from being interpreted as a null result.

n_tier = (# assets in tier) × (# usable days per asset)

Minimum requirements:
  n_T1 ≥ 2500 observations     n_T2 ≥ 1500     n_T3 ≥ 800
If a tier falls short:
  (a) extend the sample window earlier (if history permits), or
  (b) merge tiers for the pooled test and report the tier split as exploratory, or
  (c) report the tier result as underpowered, explicitly.
Never silently proceed with an underpowered tier test.

6.3 Model ladder and baselines

The nine models of §4.4 run against every feature set and every validation scheme. Baselines B1–B3 are not optional decoration — they are what makes the headline numbers meaningful.

Baselines

  • B1 Random walk
  • B2 MA / Bollinger rule
  • B3 Ridge

If a model does not beat B1 out-of-sample, say so plainly.

Classical ML

  • M1 Random Forest
  • M2 XGBoost (primary)
  • M3 LightGBM

Fixed hyperparameter search budget; SHAP for attribution.

Deep & multimodal

  • M4 LSTM
  • M5 GRU
  • M6 Attention fusion
  • M7 Regime router

M6 is the closest competitor; M7 is C3's mechanism.

Fair-comparison rules

  • Equal tuning budget. Same number of configurations searched per model family. Document the budget in the results table.
  • Equal information. Every model sees the same feature set when they are compared to each other. If M6 gets a richer feature set than M2, the comparison confounds architecture with features — report the like-for-like comparison as the headline and the richer comparison as supplementary.
  • Equal seeds. 5 seeds for the reported configurations of every model.
  • Naive baselines get no tuning (they have none to get) but do get the same information: the random-walk baseline predicts the zero return, and the MA rule is evaluated on the same out-of-sample windows as the models.

6.4 Validation strategies

SchemeDefinitionRoleWhy it is in the design
V1 Fixed chronological70 / 15 / 15, expanding window, embargoed boundariesQuick checkCheap; reproduces the convention of the four source papers so results are comparable. Never report it alone.
V2 Walk-forwardExpanding train, 252-day test folds, 61-row embargo, ~38 foldsPrimaryThe honest simulation of live operation. Fold count matches Wang (2026) for comparability.
V3 Purged walk-forwardFixed-length rolling train window (e.g. 504 days), embargoedRobustnessTests whether results depend on an expanding (ever-growing) training set — they usually do, and this exposes it.
V4 Regime holdoutTrain on bull periods, test on a contiguous bear period, and vice versaStress testThe hardest test. Directly addresses Wang (2026)'s finding that models degrade in bear markets, and it is the regime-shift scenario C3 is designed for.
V5 Asset holdoutTrain on T1+T2 assets, test on held-out T3 assetsGeneralisationThe single most important test for a multi-tier project: does a model trained on deep markets transfer to thin ones? This is where the tier structure becomes a prediction claim rather than a description.

Table 6.3 — Validation schemes. V5 is unusual and valuable: it converts the tier analysis from descriptive into predictive, and it is the test that makes C1 more than a description of the past.

Regression (on y_ret)

MetricFormulaNote

Classification (on y_dir)

MetricFormulaNote
Accuracy(TP+TN)/nReport with balanced accuracy. Do not headline it alone.

Financial (from the backtest)

Annualised return, annualised volatility, Sharpe, Sortino, MaxDD, CER, turnover, and the number of trades — as specified in §4.6.2. Every financial table includes a buy-and-hold row for the same asset and window.

Metrics to use instead of the ones the proposal lists

DSTAT — not a standard term; the intended meaning is directional accuracy. CER — define precisely (§4.6.2) or omit. SMAPE — problematic near zero on returns; use it on price levels only, or drop it. SHAP — not a metric but an interpretability method; it does not belong in a metrics list. R² on a directional model — undefined; do not report it.

Three statistical cautions for the thesis

1. Granger causality is not causality. It tests incremental predictability, not a causal mechanism. If you report it, report it as predictive precedence and explicitly state that it does not establish a causal channel. A reviewer will check for exactly this overreach, because "the sentiment causes the price" is the most tempting and most indefensible sentence in the whole project.

2. Multiple comparisons. With ~20 assets × 3 tiers × 9 models, the raw comparison count is in the hundreds. Without correction, a 5% significance level produces false positives by the dozen. Benjamini–Hochberg is the minimum defence, and stating the correction in the thesis is itself a mark of rigour.

3. Endogeneity and reverse causality. A negative return produces negative news, which produces negative sentiment. So sentiment and returns are jointly determined, and the contemporaneous association is not cleanly interpretable. Kreuzer et al. (2026) address this by excluding pure market-update feeds from their corpus. Adopt that exclusion — filter out articles whose content is primarily a market recap — and document it. It is a small implementation detail with a large effect on the credibility of RQ3.

The rules

  • Seeds are recorded, not assumed. Global seed + per-model seeds, both in the manifest.
  • Dirty-tree runs are flagged and excluded from the reported results. git_dirty: false is a precondition for including a run in the thesis.
  • Environment is pinned with hashes. Not a requirements.txt with loose version ranges — a lockfile.
  • Data is fingerprinted. The hash of the input parquet files is in the manifest, so a result can be tied to an exact data snapshot.
  • One command reproduces. make experiment RUN_ID=exp_20260514_0031 re-executes that exact configuration.
  • The registry is the source of truth. Every table and figure in the thesis is generated from the registry by scripts/build_report.py. No number is typed by hand into a document. This is the single highest-leverage discipline in the project: it eliminates transcription errors and makes every claim verifiable.
